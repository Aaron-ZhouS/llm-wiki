# 【福利包】5 个 90% 的人都会撞的配置坑 + 解决方案

## 坑 1：AppSecret 忘了，只能重置

### 现象
配置 WorkBuddy 时手抖复制错，或者关掉页面后再回来——**AppSecret 找不到了**。开发者平台上只显示 `********` 这种掩码。

### 原因
微信官方设计：**AppSecret 只在生成/重置时完整显示一次**。这是安全机制，不是 bug。

### 解决方案

| 步骤 | 操作 |
|---|---|
| ① | 登录 https://developers.weixin.qq.com/platform/ |
| ② | 我的业务 → 公众号 → 开发密钥 |
| ③ | 点「重置」→ 管理员扫码 |
| ④ | **立刻复制新密钥**到密码管理器 |
| ⑤ | 同步更新 WorkBuddy 的 `~/.workbuddy/.env` |

### 预防
- 用 1Password / Bitwarden / 微信收藏加密笔记存密钥
- **不要**放在普通微信聊天记录、Notion 公开页、飞书群里

## 坑 2：报错 40164（ip not in whitelist）

### 现象
配置都正确，但 WorkBuddy 推送时报：

```
errcode: 40164
errmsg: ip not in whitelist hint: [58.xx.xx.xx]
```

### 原因
你电脑的**公网出口 IP** 没加进公众号的 API IP 白名单。

- 微信看到的 IP ≠ 你百度"IP"查到的 IP（百度显示的是出口 IP，但有时差）
- **家庭宽带 IP 是动态的**，重启路由/隔几天自动拨号就变

### 解决方案

```
步骤 ①：让 WorkBuddy 查公网 IP
   输入："我的公网 IP 地址是多少？"

步骤 ②：去 https://developers.weixin.qq.com/platform/
   我的业务 → 公众号 → API IP 白名单

步骤 ③：把 IP 粘进去 → 保存

步骤 ④：让 WorkBuddy 重新推送测试
   输入："再推一次那篇文章，验证能不能成功"
```

### 预防
- **每周日晚上**让 WorkBuddy 自动查一次 IP，有变化就提醒你
- 商业宽带/固定 IP 用户可省这一步

## 坑 3：未认证订阅号推不了某些接口

### 现象
token 能拿到，草稿箱能推，但调用某些接口时报错：

```
errcode: 48001
errmsg: api unauthorized hint
```

### 原因
未认证订阅号的**接口权限比服务号少**。基础推送草稿箱可以，但素材管理、用户分析、客服消息等高级接口需要认证。

### 解决方案

| 方案             | 适合                     |
| -------------- | ---------------------- |
| **A. 升级认证订阅号** | 个人用，每年 300 元           |
| **B. 升级服务号**   | 企业用，每年 300 元起          |
| **C. 接受现状**    | 只用 WorkBuddy 推草稿箱，完全够用 |

### 我的建议
**90% 的一人公司场景选 C**——WorkBuddy 自动推草稿箱的功能，订阅号完全够用。你只需要：
- AppID + AppSecret ✅ 订阅号能给
- 推草稿箱 ✅ 订阅号能用
- 自定义菜单、用户标签 ❌ 需要认证

不要为了用不到的功能花 300 块/年。

## 坑 4：Node 服务随 WorkBuddy 会话结束被清理

### 现象
WorkBuddy 帮你起了个本地 Node 服务（比如写作助手工作台），但你**关掉 WorkBuddy 后服务也死了**。下次打开 WorkBuddy，工作台连不上，报错"连接失败"。

### 原因
WorkBuddy 默认的子进程会随父进程退出。如果你的写作助手是 Node 服务跑的，没配自启动就必死。

### 解决方案

```
步骤 ①：把 Node 服务配置成"Windows 登录自动启动"
   - 用 pm2: pm2 start app.js --name wechat-assistant
   - 用 nssm: 把 Node.exe 注册成 Windows 服务

步骤 ②：Mac 用户用 launchd
   - 写一个 .plist 文件放到 ~/Library/LaunchAgents/
   - launchctl load 启用

步骤 ③：验证
   - 重启电脑
   - WorkBuddy 不开
   - 浏览器访问 http://localhost:3000
   - 能正常打开就 OK
```

### 预防
- 任何"长期运行"的服务，都要明确"自启动"策略
- 不要假设"我开 WorkBuddy 它就会自己起来"

## 坑 5：去重正则把中文全删了

### 现象
让 WorkBuddy 抓百度热搜、微博热榜等外部热点，结果**60 条数据只剩 1 条**，或全部变成乱码。

### 原因
典型的 bug：用了 `[\\s\\W]` 这种正则去重，**`\\W` 会匹配所有非单词字符，中文不在「单词字符」定义里**，所以中文被全部删除。

### 解决方案

**错误写法**（删中文）：
```javascript
const unique = [...new Set(items.map(s => s.replace(/[\s\W]/g, '')))]
```

**正确写法**（只去空白+标点，保留中文）：
```javascript
const unique = [...new Set(items.map(s => s.replace(/[\s\p{P}]/gu, '')))]
// 或者更简单：直接 Set 去重，不清洗字符
const unique = [...new Set(items)]
```

### 预防
- 涉及中文文本处理时，**永远不要用 `\\W`**
- 用 `\\p{L}`（所有字母包括中日韩）、`\\p{P}`（标点）这种 Unicode 属性更安全
- 跑完正则先 `console.log` 看几条样本，肉眼确认没把中文删了

## 🎯 5 个坑的一句话总结

| # | 坑 | 一句话解决 |
|---|---|---|
| 1 | AppSecret 找不到 | **密码管理器存**，忘了就重置 |
