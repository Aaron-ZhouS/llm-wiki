# 【福利包】知识库 10 条 WorkBuddy 指令清单（编译/查询/体检/AI 排版）

> 来自公众号文章《用了 5 年 Obsidian，我才发现知识库一直"缺一块"》。对应评论区关键词 **"指令"**。
>
> 适用读者：你已经搭好 WorkBuddy + Obsidian 工作流，需要一套"开箱即用"的指令。

---

## 一、初始化类（3 条）

### 指令 1：建库骨架

```
你现在是这套个人知识库的搭建与维护 Agent。请在当前 Obsidian Vault 根目录中，
搭建一套可长期增量维护的 LLM Wiki。
[粘入"目标 + 结构 + AGENTS 规则 + 模板 + 验收"五段式]
```

### 指令 2：批量导入旧笔记

```
读取当前 Vault 根目录所有现有的 .md 文件，按 AGENTS.md 规则增量编入 wiki：
- 已存在概念归到 concepts/，已存在实体归到 entities/
- 重复内容合并到对应页面，不重复建页
- 完成后告诉我新建、更新了哪些页面
```

### 指令 3：装一个"使用说明书"在库根

```
基于我已经搭好的 AGENTS.md，给我写一份 5 分钟快速上手指南，保存为 README.md。
让一个完全没用过这个库的同事看完就能开始用。
```

## 二、编译类（3 条）

### 指令 4：日常增量编译

```
AGENTS.md 的规矩你都读过了。去把 raw/ 里新到的那批文章编进 wiki：
该开页开页，该并页并页，收工前把 index.md 和 log.md 也捋顺。
```

### 指令 5：单文件精编译

```
把 raw/articles/<文件名> 这篇文章精编进 wiki：
- 概念归 concepts/（查重后再建页）
- 实体归 entities/
- 来源摘要放 sources/
- 双链用 [[双链]] 连到相关页面
- 完成后告诉我新建/更新了哪些页面
```

### 指令 6：冲突处理（观点打架时）

```
raw/ 里新进了两篇对"X"这个话题说法冲突的资料。
请按 AGENTS.md 的"冲突处理规则"处理：
- 两说并排放着
- 各自注明出处和日期
- 加一行"这里有分歧，等我裁"
- 不要擅自覆盖任何一方的结论
```

## 三、查询类（2 条）

### 指令 7：精准查询（带页面指引）

```
根据 wiki，新手学 <话题> 最容易卡在哪几步？
回答时先翻 index.md 圈出相关页面，只读这几页。
最后告诉我依据来自哪几页。
```

### 指令 8：多视角对比

```
根据 wiki，<观点 A> 和 <观点 B> 的说法有什么不一样？
各自依据来自哪几篇原始资料？
如果有冲突，请明确告诉我哪些地方冲突。
```

---

## 四、维护类（2 条）

### 指令 9：每周体检（建定时任务）

```
帮我建个定时任务，每周六晚上九点半跑一次，内容是：
给知识库做一轮体检，重点查三样：
- 哪条双链点过去是空的
- 哪一页成了没人引用的知识
- 哪两页的说法互相对不上
发现问题先列给我看，我确认了再改，改完记进 log.md。
```

### 指令 10：每日增量（建定时任务）

```
帮我建个定时任务，每天早上七点半跑一次，内容是：
raw/ 里要是躺着还没编译过的新文件，就按 AGENTS.md 里定好的章法
把它们编进 wiki，index.md 和 log.md 顺手带着更新；
raw/ 里没动静，这天就什么都不用干。
```

---

## 📌 几个指令设计的小心机

- **每条指令结尾都加"告诉我新建/更新了哪些页面"** —— AI 干完活必须给你清单，不然你不知道它动了啥
- **冲突类指令明确"不要擅自覆盖"** —— 这是 AGENTS.md 红线的强化版
- **定时任务指令必须有"先列给我看，我确认了再改"** —— 关键决策永远留给你，AI 不替你拍板
