# 【福利包】6 个新手必踩的知识库坑 + 解决方案

> 来自公众号文章《用了 5 年 Obsidian，我才发现知识库一直"缺一块"》。对应评论区关键词 **"避坑"**。
>
> 适用读者：你刚开始用 Obsidian + WorkBuddy 搭知识库，避开这 6 个坑能省一周时间。

---

## 坑 1：Web Clipper「保管库」和「保存路径」填反了

### 现象
装好 Obsidian Web Clipper 浏览器插件，剪藏公众号文章，**怎么剪都进不去**。

### 原因
插件设置里有两个看似一样、其实完全不同的字段：

| 字段 | 该填什么 |
|---|---|
| **保管库** | Obsidian vault 的名字（你建库时起的名字，比如"书房"）|
| **保存路径** | 文件夹路径，比如 `raw/articles/` |

**填反了 → 剪藏永远失败**，因为插件根本找不到目标库。

### 解决方案

```
步骤 ① 打开 Web Clipper 设置
步骤 ② 保管库 = "书房"（你 vault 的名字，注意大小写）
步骤 ③ 保存路径 = "raw/articles"（相对路径）
步骤 ④ 验证：随便剪一篇，确认文件出现在 Obsidian 左边的 raw/articles/ 下面
```

## 坑 2：AGENTS.md 一次写太厚，AI 反而不会用

### 现象
写了 1000+ 行的 AGENTS.md，**WorkBuddy 反而开始乱来**：自己改 raw 文件、不更新 index.md、合并冲突时自作主张。

### 原因
胡子哥原话——

> "给你 1000 道菜的菜单，你反而不知道怎么做菜了。"

AGENTS.md 不是越厚越好，是**越准越好**。规则太多，AI 反而抓不住重点。

### 解决方案

**30 天内只用这套最小规则集（不超过 200 行）：**

```markdown
## 你是谁
[3 行内说清]

## 地盘规矩
[raw 只读、wiki 可写、index 更新、log 追加——不超过 5 条]

## 编译的规矩
[查重 + 冲突保留 + 双链 + 出处——不超过 5 条]

## 回答问题的规矩
[先查 index → 只读相关页 → 标注依据——3 条就够]

## 红线
[2-3 条绝对不能做的事]
```

**30 天后**才会知道"自己哪里没规定清楚"，那时再加规则不迟。

## 坑 3：raw/ 文件被 AI 改坏了

### 现象
WorkBuddy 编译时**不小心改了原始资料**——可能是删了一段、改了几个字、把 PDF 转成乱七八糟的 Markdown。

### 原因
AGENTS.md 没明确写"raw 只许读，不许改"——或者写了但 AI 没把这条放在权重最高的位置。

### 解决方案

**AGENTS.md 红线段必须包含这 3 行：**

```markdown
## 红线
- raw/ 里的文件，只许读，不许改、不许删、不许移动
- 任何对 raw/ 的"修改"都必须先问我确认
- 误改了 → 立刻回滚到上一版（用 Git 或 .bak 文件）
```

外加两个保险措施：

1. **Obsidian 端开启"文件历史记录"插件**（免费的）—— 改坏了能回滚
2. **整个 Vault 用 Git 跟踪**（Vault 根目录 `git init`）—— 每周自动 commit 一次

## 坑 4：每周体检任务跑崩——发现 100 个问题怎么办

### 现象
跑了一次体检任务，AI 报告说"100 条断链、30 个孤立页、5 个冲突"——你看着就头大，**于是整个任务停了 3 个月没跑**。

### 原因
体检结果没"分级处理"。一次输出 100 个问题 = AI 等于没说。

### 解决方案

**让 AI 把体检结果分成 3 桶，每桶单独处理：**

```
每周体检任务改为：
- 紧急桶（影响知识库主干的）：断链超过 5 个的孤立页 → 列给我，我决定保留/删除
- 重要桶（影响知识质量的）：观点冲突页 → 列给我，我把我的判断写进去
- 一般桶（其他）：记录进 log.md 就行，不用立刻改
```

这样你每周只需要处理 3-5 个紧急桶问题，**10 分钟搞定**。

## 坑 5：Obsidian 关系图谱看起来很美，但没用

### 现象
花了一周调"关系图谱让它好看"——换颜色、加滤镜、改布局。

**结果：图谱变好看了，但用知识库的效率没变。**

### 原因
图谱是"展示品"，不是"工具"。它的唯一价值是**让你快速发现"哪些页面没被引用"**——其他都没用。

### 解决方案

**关掉图谱的视觉美化，**只用一个功能：

```
Obsidian → 关系图谱 → 过滤器 → "孤立页面"（0 个入链）
```

**这个过滤结果直接告诉你：哪些页面是"知识库里的孤儿"，可以考虑合并或删除。**

其他视觉美化，**全部不需要**。

## 坑 6：定时任务跑崩——AI 误删文件

### 现象
设了"每天 7:30 自动编译"的定时任务。某天早上你打开知识库，**发现有几篇笔记被 AI 误删了**。

### 原因
定时任务没加"先列给我看"约束——AI 觉得"旧了 = 没用 = 应该删"。

### 解决方案

**所有定时任务都必须包含三段式：**

```
[频率]：[每周/每天 X 点]
[任务]：[要做什么]
[确认]：[发现问题先列给我看，我确认了再改]
```

**示例：**

```
帮我建个定时任务，每天早上 7:30 跑一次：
- raw/ 里有新文件 → 按 AGENTS.md 编入 wiki，更新 index.md 和 log.md
- 没有新文件 → 什么都不做，记一笔"今日无更新"
- 不要删任何文件，不要重命名任何文件，不要移动任何文件
- 所有动作完成后只汇报"动了什么"，不直接改
```

**记住：自动化的边界 = "我不在时 AI 不能做什么"。**

## 🎯 一句话总结

> **AGENTS.md 写薄不写厚；raw/ 设只读；体检结果分桶；定时任务必确认。**

这 4 件事做好，知识库的"避坑率"能涨到 90% 以上。
