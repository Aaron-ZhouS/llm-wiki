## 一份 SOP 手册的标准 10 段（v2.0 重构）

每篇 SOP 手册统一格式，学员不用适应不同风格。
**v2.0 重构后**：对齐琪萌公众号范式（判断句 + 要点 + 场景痛点 + 认知卡点 + 解决方案 + 原话）。

```
0. frontmatter（name/description/skill_ref/audience/version/created/updated）
1. 一句话定位 + 核心心法（学员 3 秒看懂）
2. 先看清卡点（场景痛点 + 认知卡点 + 解决方案 + 原话）
3. 什么时候用 / 什么时候不用（触发信号 + 避坑）
5. 3 步调用流程 + 触发词清单
6. 输入模板（学员复制粘贴即可）
7. 关键工具（4 铁律 / 4 等级 / 4 阶段 等核心速查）
8. 输出物（拿到什么）
9. 与其他 Skill 的联动（完整闭环图）
10. 实战示例（琪萌用例 + 引用具体卡片 ID）
11. 5 条红线（学员最容易踩的坑 + AI 拒绝话术）
12. 为什么必须有这个 Skill（学员必看的价值锚定）
13. 引用（Skill 原文 + 实战案例 + 风格参考 + 维护人）
```

## 写新 SOP 的流程

**触发**：周盛说"给 X Skill 写 SOP" / 周盛新装一个 Skill 需要 SOP

**步骤**：
1. 读 `/mnt/d/Obsidian/llm-wiki/concepts/<skill-name>.md`（Skill 原文）
2. 按上面 10 段格式写 `SOP-<skill-name>.md`（v2.0 起对齐琪萌公众号范式）
3. 在本 README 学员清单追加一行
4. 同步到学员库（每个学员目录都复制一份）

## 风格参考（v2.0 引入）

SOP 手册不再只是"操作说明"，而是**学员的思维锚**——对齐琪萌公众号「微笑着前进Bright」范式：

- **判断句标题**：每节标题都是判断，不是中性描述
- **场景痛点 + 认知卡点 + 解决方案 + 原话**：四段固定结构
- **胡子哥原话必带**：每个 Skill 的核心心法用原话锚定（不是 AI 总结）
- **琪萌实战案例**：用学员自己生成的卡片 ID 作为范例

**3 篇范本原文**（都在学员库参考资料）：
- 《你花 700 块买 AI 会员，不如胡子一天一块钱的自建系统》→ 对应 SOP-可运行性检查 / SOP-知识卡片 / SOP-灵感对撞
- 《普通人赚钱地图：想清楚→做出来→靠系统复利》→ 对应 SOP-挖矿压缩机 / SOP-口播炼金
- 《你断在哪一环？——六个卡点，一条没转起来的闭环》→ 对应所有 SOP 的"卡点诊断"段

## 学员库同步约定

每写一份新 SOP，需要**同步给每位学员**：

```
/mnt/d/Obsidian/llm-wiki/SOP库/SOP-<skill>.md   ← 总库（唯一来源）
/mnt/d/Obsidian/llm-wiki/学员库/<学员名>/SOP库/  ← 学员本地副本
   ├── SOP-口播炼金.md
   ├── SOP-知识卡片.md
   ├── SOP-灵感对撞.md
   ├── SOP-挖矿压缩机.md
   └── SOP-可运行性检查.md
```

> **改 SOP 流程**：改总库 → 同步到每位学员 → 不直接改学员本地（避免版本漂移）
