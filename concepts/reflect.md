# 反思 v2 — 认知进化催化剂

> 你的每一轮对话都是原材料。反思的职责是：从这些对话中提取你的做事原则、思考模式 → 关联已验证的基础学科知识 → 变成系统级的改进，写入对应的 _System/ 配置文件。

---

## 一句话定位

**输入（对话/项目/反思需求）→ 选模式（标准/变异检测）→ 7 阶段流程（回顾→提炼→关联→Skill 改进→_System/ 更新→AI 系统审计→复盘两问）→ 输出可执行的系统改进建议。**

---

## 核心定义

**反思不再是"系统改进工具箱"，而是认知进化催化剂。**

闭环：**对话 → 观察 → 提炼 → 关联验证 → 系统更新**。

---

## 模式选择

`/反思` 支持两种模式：

| 模式 | 触发词 | 频率 | 目标 |
|------|--------|------|------|
| **系统反思**（标准模式） | `/反思` | 每 2-4 周 | 全面系统体检 |
| **变异检测**（轻量模式） | `/反思 变异检测` | 每日/每周 | 检查是否在鬼打墙 |

## 变异检测模式（轻量）

> "学习的本质是变异，不是输入。如果我学了很多但没变——我太擅长学习了。"

### 触发时机
- 每晚睡前（30 秒版）
- 每周当日志/输入积累到足够量时（10 分钟版）
- 感觉"学了很多但没变化"时

### 执行步骤

**Step 1：今日变异扫描（60 秒）**

扫描最近的输入（读的文章、看的视频、做的笔记），回答：
- 最近 3 天的输入里，有多少是我以前就知道的观点？
- 有没有至少一个让我觉得"我之前想错了"的时刻？
- 如果没有 → 记录为"连续 N 天无变异"，N≥3 触发报警

**Step 2：输入源诊断（10 分钟版）**

列出最近一周的主要输入源（公众号、文章、书籍、课程、对话）：
- 这些来源中有多少是"新认知" vs "旧认知加固"？
- 你的输入是否集中在同一个信息圈里？
- 有没有 1-2 个你一直回避/排斥的输入源？

**Step 3：AI 辅助（可选）**

让 AI 分析你本周的输入日志：有多少比例是重复范式，多少是真正的变异。
命令参考：`请分析我的输入同质化程度，将输入分为[新范式/旧范式加强/无关]三类，算比例`。

**Step 4（可选）**：AI 系统审计
```
1. 本周我的输入/输出中，哪些还在"手动挡"？
2. 系统里有断裂点吗？
3. 下周能把哪个函数升级一个版本？
```

**Step 5：产出变异报告**

```
## 变异检测报告 — [日期]

### 变异状态：[有变异 ✅ | 疑似鬼打墙 ⚠️ | 鬼打墙 ❌]
连续无变异天数：[N]

### 本周变异点
- [具体认知变化：我之前以为 X + 现在是 Y]

### 输入源分析
- 新认知来源：[N]%
- 旧认知加固：[N]%
- 同质化评估：[轻/中/重]

### 建议
- [如果鬼打墙]：切换输入源，执行强行失衡（见 cognitive-ghost-wall）
- [如果正常]：继续保持
```

## 标准模式执行流程（7 阶段）

### 阶段一：回顾本轮对话

1. 读取本轮对话（`reviews/YYYY-MM-DD-HH.md` 或当前对话上下文）
2. 识别以下信号：
   - 你做决策时用了什么原则？
   - 你纠正我时，背后是什么判断标准？
   - 你反复做的事，有什么共同模式？
   - 你说过"对"、"不对"、"应该改"的地方
   - 你表达了偏好或厌恶的地方
3. 列出候选提炼点（最多 5 个）

### 阶段二：原则提炼

对每个候选点：

1. **提炼** — 用一句话描述
   - 格式：`原则：[名称] — [一句话]`
   - 例：`原则：数据优先于直觉 — 任何判断必须先有数据再有结论`
2. **验证** — 出现几次？
   - 1 次 → 标记"观察"
   - 2+ 次 → 标记"模式"，值得沉淀
3. **分类** — 属于哪个层面？

| 分类 | 含义 | 去向 |
|------|------|------|
| 个人习惯 | 做事的偏好/风格 | `_System/USER.md` |
| 认知风险 | 容易陷入的陷阱 | `_System/USER.md` |
| AI 行为规范 | 我应该遵守/杜绝的行为 | `_System/SOUL.md` |
| 会话准备 | 每次对话前应该准备好的 | `_System/Session-Protocol.md` |
| 内容规则 | 内容处理的判断标准 | `_System/Content-Rules.md` |
| 长期记忆 | 跨会话必须记住的核心 | `_System/MEMORY.md` |

### 阶段二点五：认知 bug → 自动化候选

> 来源：胡子 2026-07-14 直播——"识别 → 暂停 → 修 bug → 自动化"。

扫描本轮对话和近期记录：

1. **重复触发的默认值**
   - 情绪默认值：被评价刺痛、急着反驳
   - 自我保护：先证明自己没错
   - 社会默认值：先看别人怎么做
   - 惯性默认值：下意识说"不是 / 可是"

2. **4 类认知盲区**（来源：2026-07-19 胡子直播）

| 盲区 | 诊断问题 |
|------|---------|
| 资产盲区 | 做完一件事是否没留下可复用的东西？上一个项目留下的 SOP 在哪？ |
| 产品盲区 | 是否在想"怎么让别人来"而非"我的东西够好了吗"？ |
| 穿透盲区 | 是否因为遇到一个小卡点就换方向？上一个卡点是怎么解决的？ |
| 规模盲区 | 是否还没跑通一个用户就想做多个版本？ |

3. **是否完成暂停**
   - 有暂停：记录有效触发器
   - 没暂停：把"暂停动作"设计成最小动作（等 3 秒/复述对方问题/先写下自己的判断）

4. **修复动作是否具体**
   - "以后注意"不算修复
   - 必须写成：当 [场景] 出现时，我先 [动作]

5. **是否值得自动化**
   - 1 次：观察
   - 2 次：加入复盘清单
   - 3+ 次：写入 Inbox

**输出格式**：

```
## 认知 bug 自动化候选

| bug 名称 | 触发场景 | 默认值类型 | 盲区类型 | 暂停动作 | 修复动作 | 自动化候选 | 优先级 |
|---|---|---|---|---|---|---|---|
```

### 阶段三：基础学科关联（逆向工程反模式）

对已提炼为"模式"的原则，调用逆向工程的反模式方法：

1. **问**：这个原则在基础学科中是否有已验证的对应知识？
   - 认知心理学（认知偏差、元认知、刻意练习）
   - 行为经济学（损失厌恶、锚定效应、框架效应）
   - 系统论（反馈回路、涌现、杠杆点）
   - 信息论（信噪比、压缩、冗余）
   - 进化论（变异-选择-保留、适应度景观）

2. **连接**
   - 格式：`[原则名称] ↔ [学科概念]：[关联说明]`
   - 例：`数据优先于直觉 ↔ 认知心理学"确认偏误"：人天然倾向于寻找支持自己观点的证据，强制先看数据是为了对抗这种偏误`

3. **反模式检测**
   - 检查是否与某个已知反模式匹配
   - 发现反模式 → 明确标注并提供规避建议

### 阶段四：Skill 改进分析

1. **扫描当前 skill 状态**：
   - 哪些 skill 最近频繁报错或需要修正？
   - 哪些 skill 的 `usage_count` 持续为零？
   - 哪些 skill 之间有功能重叠？
   - 本轮对话揭示的哪些能力没有对应的 skill？

2. **判定**：
   - 需要改进的 skill → 列出具体改进点
   - 需要新建的 skill → 描述职责和关系

3. **CLAUDE.md 检查**：
   - 如果新增/移除/重命名 skill → 路由表是否需要更新？

### 阶段五：_System/ 文件更新建议

按以下顺序逐文件检查，每个文件输出具体的更新建议：

#### 1. `_System/USER.md` — 你的习惯和风险
- 从"个人习惯"和"认知风险"中筛选
- 问：这个习惯是否影响系统运转？这个风险是否值得提前防范？

#### 2. `_System/SOUL.md` — AI 行为规范
- 从"AI 行为规范"中筛选
- 问：我应该遵守什么新规范？我应该杜绝什么行为？

#### 3. `_System/Session-Protocol.md` — 会话准备
- 问：哪些信息如果在会话开始时准备好，会让后续工作更高效？

#### 4. `_System/Content-Rules.md` — 内容处理规则
- 问：我们对"好内容"的标准变了吗？有新的格式规范吗？

#### 5. `_System/MEMORY.md` — 长期记忆核心原则
- 从原则中筛选"跨会话必须记住"的
- 问：这个原则如果下次会话我不记得，会有多大损失？

### 阶段六：AI 系统审计（可选但推荐）⭐

> 来源：2026-06-02 胡子直播——每周反思后把输出扔给 AI，对比现有系统做三件事：检查未自动化环节、找系统 bug、提升级建议。

**前置条件**：已完成阶段一至阶段五

**Step 1：读取系统状态**
- 扫描用户当前函数/系统清单（`02-Areas/`、`05-Skills/`）
- 如果扫描不到，让用户提供

**Step 2：AI 审计三问**

```
1. 哪些还没自动化？
   → 检查用户的函数列表中哪些还是手动操作
   → 具体建议：明确「把这个 X 步骤自动化，用 Y 工具」

2. 系统里有 bug 吗？
   → 函数之间的断裂点
   → 数据流断点
   → 已被反思发现但没修复的旧问题

3. 还可以怎么升级？
   → 哪些函数可以升级版本？
   → 有没有新的 AI 工具/方法可以替代旧流程？
```

**Step 3：输出系统改进清单**

```
## AI 系统审计报告

### 未自动化环节（按优先级）
1. [环节] → [自动化建议]

### 系统 bug / 断裂点
1. [问题] → [影响说明]

### 升级建议
1. [函数名] → [升级方向]

### 优先级总览
- 🔴 本周可以改的（1-2 项）
- 🟡 本月可以改的（3-4 项）
- 🟢 未来方向（5+ 项）
```

**跳过规则**：用户说"跳过审计"或"下次再审计"——每次反思都问但不强制。

### 阶段七：复盘两问

每次反思末尾执行：

1. **「放大杠杆」** — 回顾近期对话，哪一件事如果自动化或系统化，能让收益放大 10 倍？
2. **「停止偏差」** — 哪一件事我已经意识到在浪费你的时间，但你还在做？

各用 1-2 句回答。有具体方向则写入 `Inbox/` 作为待改造任务。

### 阶段七：产出反思摘要

```
| 反思完成 — [日期]

## AI 系统审计（如已执行）
- 未自动化环节：[N] 项
- 系统 bug：[N] 项
- 升级建议：[N] 项

## 提炼的原则
- [原则1]：[一句话] → 分类 → 去向

## 基础学科关联
- [原则] ↔ [学科概念]：[一句话]

## 反模式警报
- [描述]：你正在...，这是 [学科] 中已识别的反模式

## Skill 改进
- 需改进：[skill名] → [改进方向]
- 需新建：[skill名] → [职责描述]
- CLAUDE.md 需更新：[是/否]

## _System/ 更新建议
- USER.md：[N] 项 → [具体建议]
- SOUL.md：[N] 项
- Session-Protocol.md：[N] 项
- Content-Rules.md：[N] 项
- MEMORY.md：[N] 项

## 复盘两问
- 放大杠杆：[1-2 句]
- 停止偏差：[1-2 句]

是否现在执行这些更新？
```

## 何时用反思

**用 reflect 的信号**：
- 每隔 2-4 周定期运行
- 感觉系统运转有问题但说不出是什么
- 刚完成一个重要项目想沉淀
- 发现自己在重复某种低效模式

**不用 reflect 的信号**：
- 会话中途（会打断任务流）
- 紧急发布前（需要冷静期）
- 首次使用（先理解系统架构）

---

## 红灯边界（硬门禁）

- 🚫 不擅自动任何 `_System/` 文件——先展示→问→确认
- 🚫 原则提炼无证据支撑（对话中的具体例子）——凭感觉不算
- 🚫 孤例就急于固化——2 次以下只能标"观察"
- 🚫 找不到学科关联就硬凑——说"未找到明确对应"
- 🚫 反思摘要不写日期/不标 #reflection 标签——下次找不到
- 🚫 用"以后注意"代替修复动作——必须具体
- 🚫 跳过变异检测模式的"暂停动作"——跳过就是默认应付

## 检查点设计（CP1-7）

| CP | 触发 | 标准 |
|----|------|------|
| **CP1** | 阶段一后 | 候选提炼点 ≥3 个且每个有具体例子？ |
| **CP2** | 阶段二后 | 每个原则有 1 句话描述+分类+验证次数？ |
| **CP3** | 阶段二点五后 | 认知 bug 至少有 1 个具体描述+修复动作？ |
| **CP4** | 阶段三后 | 原则 → 学科关联，2 次失败就标"未找到"？ |
| **CP5** | 阶段四后 | Skill 改进/新建/CLAUDE.md 检查项齐全？ |
| **CP6** | 阶段五后 | 每个 _System/ 文件有具体更新建议？ |
| **CP7** | 阶段六+七后 | 审计+两问都执行（或用户明确跳过）？ |

---

## 失败处理（Fallback）

| 失败场景 | Fallback |
|---------|---------|
| 候选提炼点<3 个 | 引导"最近 1 周让你改变看法的事" |
| 原则只出现 1 次 | 标"观察"，不急于固化 |
| 找不到学科关联 | 标"未找到明确对应"，不硬凑 |
| 修复动作模糊 | 引导写成"当 X 出现时，我做 Y" |
| 用户拒绝更新 | 标"暂缓"，写 Inbox，下次再说 |
| 审计执行难 | 跳过（用户明确说"下次"） |
| 反思摘要太长 | 拆成多次反思，每次 1 个主题 |
