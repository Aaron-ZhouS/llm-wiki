# AI上下文配置工程 v2

> 大模型代表智商，上下文代表你。
> 你请了个智商很高的人来上班，但你没告诉他你是谁、要做什么、东西在哪。然后你说"这人不行"——其实是你不行。

---

## 一句话定位

**输入（AI 配置需求）→ 5 步骤（身份路由/思考链/压缩/按需加载/统一输出）→ 输出可落地的 AI 系统配置（CLAUDE.md / Agent.md）→ 验证+迭代。**

---

## 核心洞察

**大模型之间的能力差距，远小于"有上下文"和"没上下文"之间的差距。**
**DeepSeek v4 配上好上下文，吊打 GPT 配空提示词。**

---

## 职责

帮你把 AI 从"一个聪明但不知道干嘛的实习生"变成"一个清楚你所有业务细节的高级助手"。核心三件事：

1. **告诉 AI 你是谁**（身份声明）
2. **告诉 AI 怎么想**（思考链）
3. **告诉 AI 东西在哪**（路由+按需加载）

---

## 使用场景

### 适合
- 刚接触 AI Agent（Claude Code / Cursor / 自定义 Agent），想系统配置
- AI 回答总是"飘"——答非所问，或者答得很深刻但和你的问题没关系
- 有多个 Skill/工具，需要告诉 AI 什么场景用什么
- 知识卡片/数据量大，需要接入 RAG 或向量化搜索
- 团队多人使用同一套 AI 系统，需要标准化配置

### 不适合
- 只用 AI 做一次性问答（不需要持久上下文）
- 当前配置已经稳定出活（不要为了改而改）
- 完全不懂大模型基础概念（先了解 token、上下文长度等）

## 机制说明

### 3.1 大模型 vs 上下文

```
大模型 = 智商（天生的理解、推理能力）
上下文 = 你（你是谁、要做什么、东西在哪）

你的智能体的上限 = 你明确告诉它你到底想让它干什么
```

大模型之间的智商差距正在缩小（DeepSeek v4、Kimi 3.8、Claude、GPT 都足够好）。**但上下文的质量差距可以差 100 倍**。

### 3.2 厨师比喻

```
大模型 = 厨师（手艺好）
上下文 = 食材 + 菜谱 + 工具 + 厨房管理

巧妇难为无米之炊。
你请了个五星大厨，不给食材不给菜谱，说"这个饭店靠你了"——完蛋。
```

很多人开个小饭店，非要请五星大厨。别说用不到，食客也尝不出来好赖。

### 3.3 上下文压缩的必然性

不同模型的上下文窗口不同（1M / 128k / 256k token）。当内容超过窗口上限时，模型会自动压缩。

**压缩必须有标准：** 如果你不告诉它什么保留、什么丢弃，到了压缩的时候，真正重要的东西可能就被压缩没了。

### 3.4 思考链的 Bug

直接让 AI 挖根源会导致"答非所问"——它找到了深层问题，但忘了你最初问的是什么。

**正确做法：** 先回答表面问题，再深挖深层原因，最后重新组织排序。

## 执行步骤（5 步）

### Step 1：编写身份路由文档（CLAUDE.md / Agent.md）

**做法**：

```
1. 身份声明
   我是谁，我的角色是什么
   我希望 AI 以什么身份和我协作

2. 高频任务
   列出我每天最重要的工作任务（3-5 条）
   每条任务给出明确的执行指令

3. 路由目录
   遇到什么情况找什么 Skill/工具
   格式：问题类型 → 调用什么 → 路径在哪

4. 目录结构
   简单的目录说明（不用全量，只写 AI 需要知道的）
```

**关键原则**：
- **不要一次全给**——一个人刚入职，把所有规章制度全给他没用
- 只放最常用的几道菜——给你 1000 道菜的菜单，反而不知道怎么做菜
- 后续通过 Skill 的 `when_to_use` 字段按需加载

**通过标准**：AI 能准确回答"你是谁"、"你主要干什么"、"遇到某类问题应该找什么"

### Step 2：设计思考链

**所有需要 AI 分析/回答的场景，思考链必须是 3 层**：

```
第 1 层：回答表面问题
  - 用户问什么，先答什么
  - 不要跳步，不要直接挖根

第 2 层：深挖深层原因
  - 在表面问题回答完后，再分析"这个问题背后可能是什么"
  - 给出深层分析

第 3 层：重组排序
  - 把表面问题和深层分析结合起来
  - 按重要性重新排序输出
```

**为什么**：
- 直接挖根 → AI 会忘掉原始问题 → 回答"飘"了
- 先答表面 → 保留原始问题的锚点 → 再挖根时不脱节

**通过标准**：测试 3 个不同场景的问题，AI 的回答既不"飘"也不只停留在表面

### Step 3：制定压缩策略

**在配置文档中明确告诉 AI 压缩规则**：

```
当上下文需要压缩时，按以下优先级保留：
1. [优先级最高] 身份声明和路由规则 —— 永远保留
2. [高优先级] 当前正在执行的任务上下文 —— 保留
3. [中优先级] 用户的原始问题/请求 —— 保留摘要
4. [低优先级] 历史对话记录 —— 可以先丢弃
5. [可丢弃] 示例代码、详细说明 —— 压缩为摘要
```

**通过标准**：在长对话（超过上下文窗口）后，AI 仍然记得你是谁、当前在做什么任务

### Step 4：按需加载 Skill 和工具

**每个 Skill 的 frontmatter 必须写清楚 `when_to_use`**：

```yaml
when_to_use: >
  适合：[什么场景调用此 Skill]
  不适合：[什么场景不要调用此 Skill]
```

**关键规则**：
- 不要把所有 Skill 一次性全加载到上下文
- AI 根据用户问题 + `when_to_use` 判断是否需要加载
- 没写 `when_to_use` 的 Skill → AI 不会知道什么时候该用

**工具同理**：分类存放 + 路由文档说明

**通过标准**：AI 不会在不需要时调用无关 Skill，也不会在需要时找不到对应 Skill

### Step 5：统一输出结构

**所有 Skill 和系统提示使用统一的输出格式**：

```json
{
  "analysis": "分析内容",
  "conclusion": "结论",
  "action": "建议行动"
}
```

**为什么**：
- 统一结构 → 下游处理不需要解析多种格式
- JSON → 方便程序化处理和组合
- 减少 AI 在格式决策上的 token 消耗

**通过标准**：所有 AI 输出都遵循同一结构，下游可以直接解析使用

## 注意事项（6 条）

1. **最少且必要** — 不是越多越好。上下文质量 > 上下文数量。1000 道菜的菜单不如 5 道拿手菜。
2. **Skill 会被大模型吃掉** — 你写的 Skill 一旦让 AI 运行，就会进入它的训练语料（好模型会吸收好 Skill）。
3. **不同模型不同能力** — DeepSeek 是文本模型，不具备多模态。别骂它不会画图。配置前先搞清楚模型的能力边界。
4. **KV 缓存 / 提示词缓存** — 第一次发送长内容消耗 token 多，第二次命中缓存消耗就少。
5. **不要一次性全给** — 和带新人一样，先给核心信息，后续按需补充。
6. **给例子比描述强** — 模型会从例子中学习。如果表示不清楚，给一个相关案例比写三段描述有效。

## 何时用 AI 上下文配置

**用 ai-context-config 的信号**：
- 刚接入 AI 觉得"不好用"
- 需要配置身份/路由/决策链
- AI 回答总是"飘"、答非所问
- 知识卡/工具数量增多需要组织

**不用 ai-context-config 的信号**：
- 已有稳定 AI 配置且效果满意
- 纯对话式一次性问答
- 完全不懂大模型基础概念

---

## 红灯边界（硬门禁）

- 🚫 一次给 AI 1000 道菜的菜单 → 5 道拿手菜就够
- 🚫 让 AI 跳过表面问题直接挖根 → 会"飘"
- 🚫 压缩策略不写明 → 重要信息可能丢
- 🚫 Skill 没 `when_to_use` → AI 不知道何时用
- 🚫 输出格式不统一 → 下游解析困难
- 🚫 期待小饭店里的五星大厨 → 匹配模型能力 + 你的需求
- 🚫 觉得"AI 不好用"就换模型 → 90% 是配置问题不是模型问题

## 检查点设计（CP1-5）

| CP | 触发 | 标准 |
|----|------|------|
| **CP1** | Step 1 后 | AI 能回答"你是谁/主要干什么/问题找什么"？ |
| **CP2** | Step 2 后 | 3 层思考链对 3 个测试场景都不"飘"？ |
| **CP3** | Step 3 后 | 长对话（超窗口）后 AI 还记得身份？ |
| **CP4** | Step 4 后 | 按需加载正确（不调无关 Skill）？ |
| **CP5** | Step 5 后 | 所有输出符合统一结构？ |

---

## 失败处理（Fallback）

| 失败场景 | Fallback |
|---------|---------|
| AI 不记得我是谁 | 重写身份声明，更突出（高对比度） |
| AI 回答"飘" | 强制走 3 层思考链（Step 2） |
| 压缩丢失重要信息 | 调高优先级（加入"永远保留"清单） |
| AI 调用无关 Skill | 补充 `when_to_use`，明确"不适合"场景 |
| 输出格式乱 | 强制 JSON 或 Markdown 模板 |
| 长对话卡住 | 启用压缩策略（不让 AI 自动决策） |
