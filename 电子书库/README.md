# 电子书库

> 专门存放「大盛读过的电子书」的结构化笔记的地方。
> 原件 PDF/EPUB 放回 D 盘 `08 电子书/`(本库**不存原件**,只存 markdown 笔记)。
> 每本书独立成文件,便于 Obsidian 改稿、git 备份、二次复用(转口播 / 公众号 / 知识卡片)。

---

## 触发词（AI agent 必读）

**用户说以下任何一句,立刻按对应动作处理:**

| 触发词 | 动作 |
|--------|------|
| "这本放电子书库" | 把当前笔记写到 `电子书库/` |
| "笔记整理一下放电子书库" | 整理当前读书笔记,归档到本库 |
| "写一本电子书:书名 XXX" | 新建一篇笔记,文件名 `YYYY-MM-DD-书名-电子书.md` |
| "归档电子书" | 把已读笔记从草稿目录归档到本目录,添加 `status: read` |
| "扫描电子书架" | 扫 D 盘 `08 电子书/` 生成待处理清单 |

**不要做的:**

- ❌ 不要把原件 PDF/EPUB 复制进 vault(放回 D 盘原位)
- ❌ 不要写到 `Articles/`(那是图片导入归档,不是电子书库)
- ❌ 不要写到 `Knowledge-Cards/`(那是单点知识卡)
- ❌ 不要写到 `/home/aaron/workspace/`(那是临时草稿)

---

## 文件命名规范

```
YYYY-MM-DD-书名-电子书.md
```

示例:
- `2026-10-06-可运行的知识-电子书.md`
- `2026-10-06-纳瓦尔宝典-电子书.md`

---

## 单篇笔记 frontmatter 标准

每篇笔记开头必须包含:

```yaml
---
title: 书名
type: ebook-notes  # 或 ebook-reading
status: to-read | reading | read
created: YYYY-MM-DD
finished: YYYY-MM-DD  # 读完填
author: 作者名
isbn: 978-XXXXXXXXXX
douban: https://book.douban.com/subject/XXXXX/
source_file: D:/08 电子书/书名.pdf  # 原件位置
tags: [主题1, 主题2, 主题3]
audience: 一人公司创始人 / IP 主理人
summary: 一句话简介(200 字内)
key_takeaways:  # 3-5 条核心收获
  - 收获 1
  - 收获 2
  - 收获 3
related:  # 相关知识卡/笔记
  - "[[Knowledge-Cards/xxx]]"
  - "[[小报童文稿/xxx]]"
---
```

## 文件结构（每本电子书正文内）

按用户选择的默认档位 = **结构化笔记**:

```markdown
# 书名

[基础信息简介 200 字]

---

## 1. 目录树

[书的目录结构,2-3 级即可]

## 2. 章节摘要（每章 200-500 字）

### 第 1 章 章节名
[核心观点 + 案例 + 我的理解]

### 第 2 章 章节名
...

## 3. 金句卡片（10-20 条）

> "金句原文" —— 第 X 章
> 我的理解: ...

> "金句原文" —— 第 X 章
> 我的理解: ...

## 4. 我能用在哪里（与一人公司/口播/公众号的连接）

- 连接 1:[具体场景]
- 连接 2:[具体场景]

---

## changelog
- 2026-10-06 初稿
- 2026-XX-XX 读完全书,更新 status 为 read
```

```text
D 盘 08 电子书/ 放一本 PDF
   ↓

   ↓
Hermes 调用本 skill,生成笔记落到电子书库/
```

## 与其他目录的关系

| 目录 | 用途 | 是否同步 |
|------|------|----------|
| `Articles/` | 图片导入归档 | 不进 |
| `Knowledge-Cards/` | 单点洞见卡 | 二次复用 |
| `口播素材/` | 视频号 30-40 秒口播 | 二次复用 |
| `小报童文稿/` | 小报童长文 | 二次复用 |
| `电子书库/`(本目录) | **电子书结构化笔记** | ✅ |
| `D 盘 08 电子书/` | **原件 PDF/EPUB** | ✅ |
